# Implementation audit — 2026-09-18

Required by `docs/SCOPE-ADDENDUM-480B.md` §1–§3 and §22. Measured against
`docs/SCOPE-ORIGINAL.md` (the requirement) and `SCOPE.md` (the recorded
status) at revision `6cc3f68`, by reading every file under `src/`, `tools/`,
`benchmarks/` and `tests/`, tracing each mechanism from its entry point to
the storage or device operation it ends in, and checking the claims that
depend on things outside the repository (FreeToken's flags, FlowRunner's
configuration, llama.cpp's API) against those things.

Classification follows the addendum: **IMPLEMENTED** means reachable through
the intended production path and doing what the scope requires. A mechanism
that is real, tested and measured but that nothing in an inference run ever
calls is **DISCONNECTED**, however good it is.

## The finding that frames all the others

**No production path exists in which TierInfer's storage, cache, VRAM or
policy code sits under a running model.** The only code in the repository
that runs inference is `tools/trace/tierinfer_trace.cpp`, and it does two
things: it reads the `ffn_moe_topk-<layer>` tensors through llama.cpp's
public `cb_eval` hook (real, and the source of every routing trace), and in
"assist" mode it issues `posix_fadvise` hints — which `benchmarks/residency.py`
and `benchmarks/inloop.py` measured to move residency by nothing
(`benchmarks/REAL-ROUTING.md`, 616.9 GB of DONTNEED, residency unchanged).
During every real inference this project has run, 100 % of weight I/O was
Linux mmap demand paging. `SCOPE.md` goal 6 says as much in its last
sentence ("a llama.cpp loader [is] the remaining work"); the audit's job is to
say it at the top, because it decides what the 480B validation can and cannot
measure:

- **Can be measured on the real model:** expert addressing across shards;
  NVMe→RAM streaming, RAM cache hits/misses/evictions, prefetch
  issued/useful/late/unused/stalls, RAM→VRAM transfers and VRAM residency —
  all driven by *routing captured from the real model* and executed against
  the *real files on the 4M2*, with md0 and member-device counters.
- **Cannot be measured until a loader exists:** tokens/s of
  "llama.cpp + TierInfer" (addendum §16), because there is no such binary.
  Recording that plainly is the deliverable §23 asks for; inventing a number
  is the thing it forbids.

The exact missing integration point is in §"llama.cpp integration" below.

## Repairs this addendum makes (in the addendum's order of priority)

Correctness → integration → observability → failure safety → performance.

1. **Sharded GGUF** — model reader over all shards; shard path on every
   `ByteRange`; per-shard fds in `StorageBackend` and `ExpertStreamer`; tests
   with a synthetic split. (blocking)
2. **Tracker fed per token** by the prefetcher, not per admission.
3. **Prefetcher guards**: timeout routed to the exact path; non-blocking drop.
4. **Streamer close** resolves queued loads as failed instead of stranding
   their waiters.
5. **Storage stats** bounded; fadvise failure surfaced; short read checked
   before recording.
6. **Policy fields** that are modelled leave the shared telemetry schema
   (`sim.*`), and `TierPolicy` says in its name and docstring what it is.
7. **Safety audit** checks bound names, not text.
8. **Trace tool** rebuilt against llama.cpp b10482; the falsified assist
   flags are removed from the tool (the measurement that falsified them
   stays in `benchmarks/`).
9. **Docs**: README, architecture, benchmarks/README, SCOPE goal texts
   reconciled to the table above.

## What this audit does not repair, and why

- **The llama.cpp loader** (goal 6, and with it the consumers for items 4, 5,
  9, the runnable modes of scope §9, and completion items 9, 11, 14, 17, 18).
  It is the largest remaining piece of the project and lives partly inside
  llama.cpp's model loader. The addendum asks for the smallest change that
  makes the *existing* architecture real and measurable; the loader is new
  architecture. The integration point is named exactly at item 12 so the
  next piece of work starts there.
- **Trainable prerouter** (goal 8), **prefetch priority classes** and
  **coalescing in the prefetch path** (7.7), **device characteristics in the
  backend** (7.8), **FlowRunner-side consumer** (goal 12), **NVMe tier under
  FreeToken** (goal 11): scope gaps, recorded, not started here.

## Answer to §22's question

TierInfer today is **real, measured components with no spine**: every
mechanism between the GGUF directory and the GPU exists, is tested against
real files and a real card, and has numbers behind it — and none of them is
on the path of any token any model has generated. The 480B work that follows
measures those components under real routing on the real files, and says so
in those words.
